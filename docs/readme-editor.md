## Section blocks, alt text help and the accessibility check

Three additions make a site fully editable without HTML and safer to publish.

**Section blocks** (`admin/blocks-editor.js`). The Blocks editor has five section types besides the paragraph, heading, list, quote, question-and-answer and image blocks. Each writes a fixed shape of HTML and the parser recognises exactly that shape again, so round trips are lossless; anything else stays an HTML block.

- Hero: `<section class="hero">` with an `h1` or `h2`, an optional `<p class="lede">`, and an optional `<p class="buttons">` holding one `a.button` and optionally one `a.button.button-outline`.
- Features: `<section class="features">` with an optional `h2` and `<ul class="feature-list">` of `<li><h3>Title</h3><p>Description</p></li>` (the `p` may be missing).
- Call to action: `<section class="cta">` with an optional `h2`, one `p` and `<p class="buttons">` with one `a.button`.
- Contact details: `<section class="contact-details">` with an optional `h2` and a `ul` whose items are `li.contact-phone` (a `tel:` link), `li.contact-email` (a `mailto:` link), `li.contact-address` and `li.contact-hours` (text with `<br>` line breaks), each optionally starting with `<span class="contact-label">`. New blocks get English labels, or Spanish ones when the page address starts with `es-`; labels found in existing HTML are kept as they are.
- Two columns: `<div class="columns"><div>…</div><div>…</div></div>`, each column paragraphs and simple lists.

The styles are the last section of `assets/css/site.css` ("Section blocks"), built from the existing tokens, so the six colour sets and the light, dark and high-contrast themes all apply. `lib/starter.php` writes the new site's home page as a hero, a features list and a call to action.

**Alt text help** (`lib/features/alt-text.php`, `admin/alt-text.js`). Needs the same two things as the Ask a question assistant: `anthropic_api_key` in `data/config.php` (set in Settings) and the SDK in `vendor/` (`composer install`); the Features switch for the assistant is not needed. Without them the buttons do not appear and Images and files says why. The control panel address `/admin/?a=alt_text` answers JSON: GET returns `{available, reason, known}` (known is the saved descriptions by upload address) and POST `{url, lang}` with the CSRF token in `X-CSRF-Token` returns `{alt, description}`. Only files under `uploads/` are accepted (JPEG, PNG, GIF, WebP, up to 5 MB); the image is sent inline (base64) to `ASSISTANT_MODEL`. Descriptions requested from Images and files are kept in `data/alt-text.json`; calls are counted per day in `data/alt-text-usage.json` and refused after 200. Errors are logged to the server log and shown to the owner in plain words.

**Accessibility check** (`lib/features/a11y-check.php`). A `before_save` item hook for pages, posts, resources and stories parses the body with DOMDocument and stores plain-language warnings in the item as `a11y` (removed when there are none). An `after_save` hook appends them to the "Saved" message; because `page_save()` calls `flash()` after `save_item()` returns, the text is added in a shutdown function, which runs after that `flash()` and before PHP writes the session. `page_form()` and `post_form()` in `admin/index.php` print `a11y_warnings_html($existing, $type)` above the form when the function exists. The Dashboard card and the Accessibility screen (`?a=a11y`) check every item live, so items saved before this feature existed are included. No settings, no cron, no public output.

Files added: `lib/features/alt-text.php`, `lib/features/a11y-check.php`, `admin/alt-text.js`. Core files changed: `admin/blocks-editor.js` (section blocks, the Suggest a description button, and a fix so Image blocks render their fields again), `assets/css/site.css` and `admin/admin.css` (appended sections), `lib/starter.php` (home page body), `admin/index.php` (three commented one-line insertions: the warnings above the page and post forms, and the Description column and note on Images and files).
